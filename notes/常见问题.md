## JSON 

```go
type User struct {
    ID       int    `json:"id"`
    ID       *int    `json:"-"`
    Name     *string `json:"name";omitempty`
    Email    string `json:"email"`
    Password string `json:"password"`
    Coordinate Coordinate `json:"coordinate"`
    Coordinate *Coordinate `json:"coordinate;omitempty"`
    Coordinate *Coordinate `json:"-"`

    Map         map[string]string `json:"map"`
	Address     []string          `json:"address"`
}

type Coordinate struct {
    Lat float64 `json:"latitude"`
    Lng float64 `json:"longitude"`
}
```

```
json:"coordinate";omitempty: 如果字段为nil,则不输出到JSON
json:"-";   强制不输出到JSON   

不使用omitempty 和 - 的情况下,值类型永远输出默认值，引用类型永远输出 null（序列化）或 nil（反序列化）

1.反序列化
    json中slice字段不存在或者  slice是[]或null, 反序列化之后都为nil
    json中map字段不存在或者 map是{}或 null, 反序列化之后都为nil
2.序列化
    2.1 如果不传切片字段,json输出null; 如果不传map,json输出null
    2.2 如果传[]string{},json输出[]; 如果传map[string]string{},json输出{}
```

## panic recover
```
绝大多数 panic 是可以避免的，建议从以下三类常见场景着手：

一. 空指针引用（Nil Pointer）：这是最常见的 panic。养成对指针、Map、Slice、Interface 进行非空检查的习惯，尤其是在结构体方法内部。

go
// 推荐写法
func (u *User) GetName() string {
    if u == nil { return "" } // 防御
    return u.Name
}
二. 数组/切片越界：访问 slice[index] 前，用 if index < len(slice) 做边界检查；使用 for range 遍历可彻底避免索引越界。

三. 类型断言失败：使用带返回值的断言 v, ok := x.(T)，不要直接用 v := x.(T)，因为后者失败时会直接 panic。
```
